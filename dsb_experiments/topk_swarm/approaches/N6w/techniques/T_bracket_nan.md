### T?: a value bracket whose width overflows gives a scale of plus zero, and inf times zero puts infinite keys into the wrong bin, guard the scale and not the width
applies to: every equi-width bucket or fixed-point image over a value range (N6 at block and warp scope, B4 and N9 brackets, GVR style threshold bins), fp32 and bf16 keys with infinities, denormals or the largest finite values present
measured: N6w_ballot N 2048 k 1024 (full-range bracket, lo clamped to -FLT_MAX, hi to FLT_MAX, width inf, scale 32 / inf = +0): the oracle battery pattern inf_denorm failed on both key types and both requirements (duplicate index, two -inf items counted above the pivot and never emitted) in batch state/results/opt-N6w/N6w_ballot_vs_W2_packed_v3_n6ww2_n6w1_20261025_154239.json and again after a first fix that tested `width > 0 && scale < FLT_MAX` (both true for width inf and scale 0), GB200, nvcc 13.4.92, 2026-10-25. The host model approaches/N6w/model_device.py reproduces the failure (above count 1015 against 1013 items with an image above the pivot) and passes with the corrected guard, the device oracle passes on the same cells at commit 58626e3f (cards N6_w_v2 and N6_w_atom32).
evidence: fmaf(d, scale, 2^23) with d = +-inf and scale = 0 is NaN, whose bit pattern 0x7fc00000 is a large positive int32 and clamps to the top bin; d = -inf then lands in the top bin together with +inf, the bin map is no longer monotone, the pivot count includes items the emission (image above the pivot's maximum) never selects. With scale = FLT_MIN instead, d = -inf stays -inf (bottom bin) and d = +inf stays +inf (top bin).
how to use: Derive the degenerate case from the scale, `scale = (scale > 0 && scale < FLT_MAX) ? scale : FLT_MIN` (or any tiny positive value), never from the width alone, and keep the image a monotone function of the key for every input the contract admits: infinities must map to the end bins, never through a NaN. A host model of the exact device arithmetic on the oracle battery (inf_denorm, signed_zero, tie_heavy) finds this class of bug in seconds, the GPU oracle only says which pattern failed.
caveats: FTZ off (the default); with FTZ on, FLT_MIN as the fallback scale flushes to zero and the guard needs a normal value such as 2^-100. The bracket pass stays correct but slow in the degenerate case (everything in one bin, one more pass over the exact candidate range), which is the intended fallback.
