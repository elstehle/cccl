how to use: Build one candidate bit per slot (the compiler turns the per-slot compare, select and OR into a LOP3 tree, about 3.5 instructions per slot, not a chain). Above 8 slots per thread OR the masks across the warp (one REDUX per 32-bit word), zero the warp's row of a (warp, slot) table, loop over the set bits of the union (warp uniform) and store the ballot word of each such slot, then one block barrier. Warps whose union is zero skip the rest (one any-vote in the per-slot form). The others sum the popcounts of their slots over the warps, scan the slots by shuffles with the rounds of 32 slots loaded, summed and scanned side by side (chained only by the running total), write the bases to their own row of a base table and sync the warp, then the threads with a candidate loop over their set bits per 32-bit half (__ffs on a word is 3 instructions, __ffsll is 10) and compute rank = base[warp][slot] + popc(ballot[warp][slot] & lt_mask) from two shared loads, writing out[total_selected + rank] when the rank is below the remaining k. Up to 8 slots per thread ballot every slot, shuffle the base per slot from its owning lane (no base table, no warp sync) and load the ballot word with a compile-time offset, since the dependent lookup chain costs about what the per-slot shuffles cost there. Test the candidate with key == kth, every bit is in the prefix when the phase runs. Nothing per slot stays in registers, so the block size can be chosen for the sweep and not for the tie arrays.
caveats: nvcc 13.4.92, sm_100, random normal rows (1.4 to 11 ties at rank k). The phase is still per slot in the mask build and the scan (about 230 and 136 instructions per thread at IPT 64) and runs on 66 to 91 percent of the bf16 rows at N 4096 and above, so the bf16 price at N 16384 and 32768 is 12 to 24 percent in latency, not zero. The loops run once per candidate slot and once per candidate, flood patterns (all_equal, tie_heavy) pass the oracle and were not timed. The -0.0 normalization (about 1000 to 1250 cycles per call at 512 threads and IPT 64, measured on fp32 rows without ties) is now the largest fp32 term. The latency kernel at IPT 16 lands on ptxas's 48-register target with 20 to 72 spill bytes outside the timed chain, see the entry on the rematerialized shared window base, which cost this variant 300 to 1100 cycles per call before it was pinned.
