At 512 threads and IPT 64 the 128-register cap spills them (stack 216 bytes, 74 STL and 74 LDL, run.py LOCAL flag, T36).
how to use: Spell every ticket on a class-indexed counter (T57) so that a deterministic epilogue costs the same as the not_guaranteed one on rows without ties, which is what fp32 random rows are. Budget the warp-redundant rank (knowledge base 4.5 approach C) per item slot and not per tie: about 130 cycles per slot at IPT 4, 63 at IPT 16 and 47 at IPT 64 per run (64 VOTE, 64 STS, 64 SHFL.IDX, 64 POPC per thread at IPT 64, issue bound at two warps per scheduler on the VOTE and SHFL pipes, T33), times the share of rows whose ties do not exactly fill the remaining slots. Expect two registers per item slot for the rank phase and plan the block size so that they fit, at IPT 64 they halve the throughput occupancy. For large IPT prefer a per-candidate lookup (store the ballot word per warp and slot, write the scan bases to shared memory, let only the threads with a candidate read base and ballot and write the output directly, idea card ideas/queue/B1_det3_candidate_rank_lookup.md, not measured).
caveats: One toolkit (nvcc 13.4.92, x86 host), one node, random normal rows (bf16 rounding gives 1.4 to 11 ties at rank k, fp32 none). The phase stamps are thread 0 clocks between barriers, the prologue and pass 1 are reported as a sum. N 32768 under prefer_smaller_index exists only at 512 threads (the tie mask is 64 bits per thread) and spills there. The dropped class 1 tickets are invisible on random rows and not measured on flood patterns.
