### T?: an index-only epilogue scatters source indices by ticket straight into the consumer's k slots, no exchange buffer, no gather, no key copy
applies to: every block or warp selection whose output is indices only (B1 to B6, N6, W3, W5 finishing stages), any key width, striped or blocked tiles
measured: block_topk_air radix select, 256 threads, B200 umbriel-b200-068, CUDA 13.4.92, 2026-10-25, harness latency chain slope and throughput, file state/results/opt-B1/B1_idx_vs_B1_striped_focus_idx1_20261025_130829.json (card B1_idx_b200_20261025_1). Against the striped pairs path that exchanges keys and values through shared memory and gathers the first k slots: bf16 N 1024 k 16 1767 against 1879 cycles, k 256 1971 against 2075, fp32 N 1024 k 16 1794 against 1921, N 4096 bf16 k 16 3371 against 3885, fp32 k 64 4587 against 4847, N 32768 fp32 k 16 15164 against 17966 (5 to 19 percent). Throughput 409 against 365 Gelem per s at bf16 N 1024 k 16, 692 against 559 at N 4096, 461 against 380 at fp32 N 32768 k 16 (8 to 24 percent). Registers 32 against 37 to 38 at IPT 4, 47 to 48 against 64 at IPT 16, 248 to 250 with 0 spill against 255 with 232 to 248 bytes at IPT 128. Temp storage 2128 bytes at every N against 4128 plus N x 4.
evidence: BAR.SYNC in the latency kernel 19 against 25 (bf16) and 31 against 37 (fp32), SASS 656 against 704 instructions at bf16 N 1024 and 10296 against 12184 at N 32768 (run.py static analysis in the batch JSON). Source approaches/B1/block_topk_b1.cuh, select_indices_striped.
how to use: When the consumer wants indices, let the selection's partition stage write `out[ticket] = source_index(i)` where the ticket is a shared atomic on one counter for the strictly selected items and a second counter for the ties (bounded to the remaining k), and derive the source index from the tile position (item i of thread t is i x Threads + t on a striped tile) instead of carrying an index register per item. The caller's output array is the exchange buffer, so the temp storage no longer depends on N, the key copy that the pairs path memoizes for the gather disappears, and the three barriers of the exchange go. Keep the counter address data dependent (indexed by the item's class), see the warp-aggregation entry.
caveats: The output order is ticket order (unspecified). The ticket atomics still serialize at about one per cycle per address, so the k dependence of the epilogue stays (about 200 cycles from k 16 to k 256 at N 1024). Measured for a selection whose candidates are known from a prefix test, a sort-based primitive (W1, B6) has its indices in position already.
