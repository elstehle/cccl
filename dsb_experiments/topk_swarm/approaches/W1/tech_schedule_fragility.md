### T?: the ptxas schedule of a fully unrolled shuffle network is fragile, an epilogue predicate changed the latency of an identical fp32 bitonic top-k by 21 percent
applies to: every register-resident compare-exchange network (W1, N2, N5, W4 and B6 merge stages), any key width, latency regime above all, any variant comparison that infers cycles from stage counts or instruction counts
measured: W1_minmax_pairs (eager bitonic top-k, fp32 (key, index) pairs, fmaxf and fminf exchange) at warp N 128 with MaxK 32: k 8 and k 16 measure 1649 cycles per call, k 32 measures 2004 (1.21x), the same shape at N 256 measures 4301 (k 8, 16) against 4545 (k 32, 1.06x) and at N 64 756 against 720 (0.95x). The network is the same instantiation in all three (MaxK = 32, four tiles), the only source difference is the index store predicate `pos < K`, which is always true at k 32. B200 umbriel-b200-020 sm_100, nvcc 13.4.92, 2026-10-25, harness chain-slope latency, file state/results/opt-W1b/W1_minmax_pairs_vs_W1_reference_focus_base_pairs_20261025_131307.json (card W1_minmax_pairs_b200_20261025_1).
evidence: cuobjdump -sass of the two latency kernels: 1120 (k 16) against 1136 (k 32) instructions with the same opcode histogram (300 SHFL, 306 FMNMX, 156 FSETP, 152 SEL, 20 PLOP3, ISETP 58 against 76 for the extra predicates), but after normalizing register names 682 of the 1130 lines differ and the two schedules diverge at the first stage: ptxas reordered the whole single basic block around the different predicate set-up. The level-parallel restructuring of the same network measures 1754 at k 32 (card W1_level_pairs_b200_20261025_1), inside the swing the epilogue alone produces.
how to use: Treat a difference below about 20 percent between two network variants as unproven until both are measured in several cells and the SASS schedule is compared, not only the instruction counts. When a variant looks slower than its instruction count predicts, try the trivial perturbation first (epilogue predicate, order of independent tile sorts, a dummy dependence) before attributing the loss to the algorithm. For the final evaluation measure every (N, k) instantiation separately even when MaxK makes them the same network.
caveats: One toolkit (13.4.92), one SM. The mechanism is the ptxas list scheduler on a basic block of about 1100 instructions with 300 shuffles in flight, the pattern that triggers a bad schedule is not known, so this is a measurement rule and not a recipe for a better schedule. Not observed on the packed-word network in the same batch (W1_eager_same: identical cycles at k 8, 16 and 32 in every cell), where every stage is one shuffle and two ALU operations.
