### T57: same-kernel A/B of the ticket spelling: a constant-address shared atomicAdd with return costs 50 to 1070 cycles per call more than one atomic on a class-indexed counter, the A/B that T39 asked for
applies to: every epilogue that assigns output or buffer slots by shared atomic tickets from an unrolled item loop (B1 to B6, N6, N9, W3 and W5 finishes), all key widths, sm_100
measured: N9_w2fin against N9_w2fin2, the same N6 primitive with the warp finish and one difference in the epilogue, both against B1_n6b in consecutive lock sections of one session, B200 umbriel-b200-047 sm_100 nvcc 13.4.92 2026-10-25, harness latency chain slope, random normal input, cycles per call (control B1_n6b in parentheses). Constant addresses (one `atomicAdd(&selected, 1)` site for the items above the pivot bin and one `atomicAdd(&pivot_ticket, 1)` site for the pivot bin's members, per item slot): bf16 N 1024 k 16 1770 (1688), k 64 2095 (2042), k 256 2359 (2333), N 4096 k 16 2957 (2749), k 64 4107 (4043), k 256 5082 (4570); fp32 N 4096 k 256 5010 (4464). One atomic per item on `counter[cls]` with cls the item's class (0 above, 1 pivot), B1_idx's spelling: 1722 (1686), 1851 (2041), 1976 (2332), 2828 (2749), 3359 (4043), 4012 (4569); fp32 N 4096 k 256 3994 (4464). Difference 48 to 1070 cycles per call, 3 to 21 percent, growing with the item slots (4 at N 1024, 16 at N 4096). Cards N9_w2fin_b200_20261025_1 and N9_w2fin2_b200_20261025_1, batches state/results/opt-B4/N9_w2fin_vs_B1_n6b_focus_n9_20261025_152037.json and N9_w2fin2_vs_B1_n6b_focus_n9b_20261025_154109.json, source approaches/B4/block_topk_n6_w2.cuh (ClassTicket template parameter).
evidence: the two builds differ only in the SkipCandidates branch of `scatter` (one class-indexed atomic against two constant-address atomics), registers 40 against 46 at bf16 N 1024 (the aggregation's lane id and mask registers), the rest of the kernel identical. T23 shows the aggregated SASS shape (S2R SR_LANEID, VOTEU.ANY, FLO, S2R SR_LTMASK, POPC, elected ATOMS, SHFL.IDX per site) that the constant address produces.
how to use: When an item loop draws tickets, index the counter array by a value the compiler cannot prove uniform (the item's class, computed per item, as B1_idx does) and issue one atomic per item under the union of the classes, then branch on the class for the store. Never issue a ticket on a constant shared address from an unrolled item loop. The T23 cost attribution (about 80 cycles per aggregated site on the critical path) is confirmed by this same-kernel A/B within the measured range (12 to 67 cycles per item slot, the sites pipeline partly).
caveats: nvcc 13.4.92, sm_100, one primitive. The empty-asm spelling of T23 is a no-op (T39), the class index is the working form. With return values unused (fire-and-forget) the aggregation is wanted (T26, T27), this entry is about tickets whose return feeds a store.
