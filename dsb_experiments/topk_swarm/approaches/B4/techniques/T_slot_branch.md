### T42: a uniform branch per register slot serializes the slot bodies into dependent chains, group the slots so that the latency, not the issue count, stops being the price
applies to: every finishing stage that loops over a few register-resident candidate slots per thread with a run-time slot count (B4 passes and emission, B3's compacted passes, N6 and W3 finishes), block and warp scope
measured: B4 first build against B4_v2, same algorithm, B200 umbriel-b200-047 sm_100 nvcc 13.4.92 2026-10-25, clock64 phase stamps in the primitive (approaches/B4/profile_phases.cu, median of 32 calls, one block). With one uniform `if (j < slots)` branch per slot around a body of about 36 SASS instructions (image recompute, prefix test, three shared atomics) the first pass over 16 candidate slots of which 6 are live costs 1708 cycles at bf16 N 4096 k 16 and the two emission sweeps 1698 and 1818, about 240 cycles per slot, live or not. With the slots processed in uniform groups of four (one branch per group), the image read from a register and one atomic per slot, the same phases cost 898, 936 and 655 cycles. The harness batch B4_v2_vs_B4_base_b4_b4_20261025_153455 (state/results/opt-B4/) shows the whole call going from 7249 to 4951 cycles at that cell (card B4_v2_b200_20261025_1).
evidence: SASS of the first build (cuobjdump of the batch binary, latency kernel bf16 N 4096 k 16): per slot `ISETP`, `@P BRA`, then the slot's dependent chain `SEL, LOP3, FADD, FFMA, VIMNMX, VIMNMX, SHF, LOP3, ATOMS x3` inside a `BSSY ... BSYNC` region, the next slot's chain starts after the region, so 16 chains of about 60 cycles of dependent latency run back to back and the empty slots still pay the branch and the region.
how to use: Do not write `for j in slots: if (j < n) body(j)` with a run-time n over an unrolled register array when the body has a dependent chain of more than a few instructions. Either make the loop branch-free (predicate on validity, every slot issues, cheap when the body is short) or guard groups of 4 to 8 slots with one uniform branch, so the scheduler overlaps the chains inside a group. Hoist per-slot invariants (a key image, a twiddle) out of the pass loop into a register per slot when the slots are few, the opposite of T24's advice for the whole tile. Profile with clock64 stamps between phases (thread 0 writes `clock64()` to a device array behind a macro that compiles to nothing otherwise) before restructuring: the harness measures whole calls and the SASS instruction count did not predict this cost.
caveats: One toolkit (nvcc 13.4.92). Grouping by four still leaves separate basic blocks per group; the measured per-slot cost after grouping (about 100 cycles for a 20-instruction body at 2 warps per scheduler) is still twice the issue estimate. For a long tile (IPT 64 and above) the branch-free predicated form is the known-good shape (T32) and this entry adds nothing.
