### T?: a blocked shared-memory candidate buffer with a power-of-two per-thread stride loads with up to 32-way bank conflicts, pad the stride by one word
applies to: B3, B4, B5, B6 and every block primitive that compacts items into shared memory and hands each thread a contiguous run of them, all key widths
measured: B3 compaction path, thread t loads its cpt = N/1024 candidates from words [t * cpt, (t + 1) * cpt) of a 4-byte (bf16, key and index packed) or 8-byte (fp32) array. Plain stride against stride cpt + 1, same code otherwise, B200 umbriel-b200-020 sm_100 nvcc 13.4.92 2026-10-25, harness latency chain slope: N 32768 k 256 bf16 20909 against 28059 cycles (1.34x), fp32 20797 against 27681 (1.33x), N 16384 k 64 bf16 1.14x, fp32 1.29x, N 8192 k 64 1.05x and 1.10x, N 4096 and below 1.00x (stride 1 to 4 words). Throughput at N 32768 1.27x and 1.23x. File state/results/opt-B3/B3_padded_vs_B3_baseline_b3_pad2_20261025_131651.json.
evidence: with stride cpt = 32 words every lane of a warp hits bank (32 t + j) mod 32 = j, one bank per load instruction, 32 wavefronts per LDS, 32 loads per thread issued by all 256 threads (the baseline loaded every slot from a clamped address). With stride 33 the banks (33 t + j) mod 32 = (t + j) mod 32 are distinct. The padded word index is q + q / cpt, two instructions per stored item.
how to use: When a thread reads a contiguous run of cpt words that other threads' runs follow at a stride of cpt words and cpt is a power of two of 2 or more, store item q at word q + q / cpt (buffer size (cpt + 1) times the thread count) and read from t * (cpt + 1) + j. Any odd stride is conflict free for 4-byte words, 8-byte words keep the two wavefronts a 256-byte warp access needs anyway. Also load only the slots that are valid rather than clamping the address, a predicated LDS costs nothing when off.
caveats: The transposed alternative (item q at word (q mod cpt) * threads + q / cpt) is also conflict free but costs three instructions per stored item. A striped register layout (thread t holds items t, t + threads, ...) needs no padding but loses the index order that the scan-based tie ranks rely on, see the B3 report.
