# B1_det3: per-candidate rank lookup for the deterministic AIR epilogue
status: queued
scope: block
origin: opt-B1det phase profile of B1_det2 (approaches/B1/DET_TICKET.md section 4, T61), knowledge base 4.5 approach C
hypothesis: The warp-redundant rank of B1_det2 does per-slot work for every item slot (a ballot, a table store, a base shuffle and a popcount per slot per thread, plus one ballot word and one rank word per slot held in registers across the tie barrier) although only 1.4 to 11 items per row are tied at the k-th key. Store the full ballot word per (warp, slot) in the tie table instead of its popcount, let each warp write the per-slot bases of its shuffle scan to a small shared array, and then let only the threads that hold a candidate loop over the set bits of their candidate mask: rank = base[warp][slot] + popc(ballot[warp][slot] & lt_mask), two shared loads and a popcount per candidate, writing out[total_selected + rank] directly when rank is below the remaining k. No tie_rank or ballots array in registers, no per-slot shuffles or popcounts, no taken mask and no class 1 branch in the ticket loop.
cells it should win: every prefer_smaller_index cell of B1 with ties at rank k (bf16 at every N, fp32 on quantized or tie-heavy rows), latency from N 4096 up, throughput at N 16384 and 32768 where the two per-slot register arrays halve the occupancy or spill at 512 threads.
cost model: tie phase per run = ballots and table (about 48 per slot at IPT 4 to 24 per slot at IPT 64, placeholder from the T61 ballot half) + shuffle scan (about 150 per round of 32 slots, placeholder) + candidates per thread x (2 LDS + POPC + STS, about 60), against B1_det2's 526 at IPT 4, 1004 at IPT 16 and 3005 at IPT 64 (T61). Registers: B1_idx's count plus the mask words, against plus 2 x IPT.
focus cells: bf16 N 4096 k 64 and k 256, bf16 N 16384 k 256, fp32 N 16384 k 16 (registers only), bf16 N 32768 k 64 at 512 threads (the spill case)
boundary cells: bf16 N 1024 k 16 (the phase runs in 28 percent of rows and costs 526, the lookup must not add a barrier there), fp32 N 1024 k 16 (no ties, must stay within noise of B1_idx)
explore first: (1) build the lookup form in a copy of block_topk_b1_det2.cuh, keep the stamps, run profile_det_phases.cu first to see the tie scan half fall before any harness batch, (2) check ptxas -v for the register count at IPT 64 at 256 and 512 threads, (3) one harness batch against B1_det2 and against B1_idx under not_guaranteed, (4) the any-candidate ballot per warp to skip the per-slot ballot loop in warps without a tie.
determinism and ordering: inherent, the same index order on striped tiles as B1_det2, exact under the oracle battery including signed_zero
main risk: the loop over the set bits of the candidate mask is data dependent per thread (divergent, a few iterations), its shared loads are bank conflict free only if the table is laid out slot-major, and the ballot words must be written by every warp for every slot (IPT predicated stores stay). If the tie table is read by all threads after the barrier the shuffle scan still has to run once per warp or be replaced by a per-slot scan in shared memory with a second barrier.
cheapest kill experiment: profile_det_phases.cu at bf16 N 4096 k 64 with the lookup form: if the tie scan half does not fall below 300 cycles per run (from 571) or the latency-kernel registers at IPT 64 stay above 160, the idea is retired.
