# N6: Equi-width bucket select over the value bracket (one discriminating pass instead of radix digits)
status: queued (wave 1 candidate, same optimizer as B1, also a W3 variant at warp scope)
scope: block, warp
origin: new here. The 256-bin uniform histogram of the TRT-LLM GVR kernel (`reference/GVR_V2_ALGORITHM_REPORT.md` section 2.2 and 2.4) brought inside the block primitive, and the classic bucket select. Seed from the lead: bucket select with a wide first digit.
hypothesis: radix pass 1 spends its 8 bits on sign and exponent, which separate little on logit-like data (half of uniform values share one exponent, router logits sit in two or three binades), so bf16 always needs 2 passes and fp32 2 to 4. Instead compute a bracket [lo, hi] that provably contains the k-th largest and bin the bracket into 256 equal-width intervals with one FMA and one float-to-int per item (same per-item cost as shift and mask). hi is the block max. lo is exact and cheap: the minimum over threads of the per-thread maximum is at or below the k-th largest for every k at most 256 (256 items are at least that large), one more reduction. The bracket then covers the top about 75 percent of the values at IPT 4 and the bins hold about 3 items each at N 1024, so the pivot bin after one pass has a handful of items for any k up to 256 and the finish is a second equi-width pass over the bin's sub-range or a FINISH style small selection. bf16 in one histogram pass plus a tiny finish, fp32 the same. Exactness is as in radix select: bins are value intervals, the crossing bin is found by exact counts, items above it are selected, the bin's members are the candidates. Outliers widen the bracket and shrink the discrimination, so the loop keeps the radix digit extractor as the fallback for a pass whose pivot bin stays large.
cells it should win: block N 1024 to 32768, k 16 to 256 (lo exact), both types, random and logit-like input. With B4's top-m bound as lo, k up to 256 m. Warp scope: N 256 to 4096 with a 32-bin bracket histogram by 5 ballots per item, one pass.

cost model (placeholders July 2026 B200 as B1: histogram 85 IPT, scan plus state 410, barrier 28, redux 22):
- Bracket: per-thread max (IPT compares), two block reductions (warp redux, smem, one barrier, about 150 in total). Bin function: 1 FFMA plus 1 F2I plus clamp, about the same as the raw shift-and-mask extractor.
- Pass 1 as B1's pass: 85 IPT + 410. Finish: pivot bin of about 0.75 N over 256 items. N 1024: about 3 items, a FINISH style selection or a second pass predicated on the bin (85 times small + 410). N 32768: about 96 items, one more equi-width pass over the bin's range, 450.
- Block totals: N 1024 bf16 about 150 + 750 + 450 + 150 = 1500 against B1 1700. fp32 the same 1500 against B1 1700 to 2500 (2 to 4 passes). N 32768 bf16 about 1800 + 150 + 11300 + 450 + 150 = 13.9k against B1 24.5k, fp32 13.9k against 35.7k, B3 15.5k, B4 4.8k. So N6 is the one-pass B1, B4 remains cheaper at large N when its bound is tight, and N6 is the robust one (no candidate buffer, no overflow).
- Warp scope: redux min and max (2 times 22, fp32 redux if available, else twiddled u32), 5 ballots per item for a 32-bin index plus one bucket count per lane plus a 5-step scan, one pass about 73 + 20 IPT + 6 IPT + 220, then a finish on about N over 32 items (sort32 660 or W2). N 512 k 16 bf16: about 44 + 710 + 660 = 1400 against W3 2400, N1 2950, W5 1740.

focus cells: 1. block N 1024 k 64 bf16, 2. block N 4096 k 256 fp32, 3. block N 32768 k 256 fp32, 4. block N 1024 k 16 fp32 (both requirements), 5. warp N 512 k 16 fp32 (NSA).
boundary cells: block N 32768 k 2048 (lo needs the top-8 bound, B4 expected), block N 1024 k 512 (lo exact only to k 256, radix B1 expected).

explore first: (1) host simulation of the pivot bin size after one pass on the harness inputs (uniform fp32, bf16 logits, sorted, tie-heavy, one outlier), minutes. (2) B1 with the bin function swapped in pass 1 at N 1024 k 64 bf16 against B1, same session. (3) the finish: second equi-width pass against FINISH against B2 rounds on the bin. (4) outlier handling: switch to radix digits when the pivot bin holds more than a quarter of the candidates. (5) warp variant against W3 and W5 at N 512 k 16.

determinism and ordering: as B1 (set deterministic with the warp-redundant rank, index-only emission by ballot prefix). Signed zero: float arithmetic treats minus zero and plus zero as equal, which is the required semantics. Infinities clamp into the end bins, NaN excluded by contract.

main risk: data with a heavy tail (one huge logit) collapses the bracket's resolution, and tie-heavy bf16 data makes the pivot bin a tie class whatever the binning. Both cost a pass, not correctness. The per-item bin function may not be free against the raw extractor on B200's pipe mix (knowledge base 2.1: count and measure).

cheapest kill experiment: explore item 1 then item 2. If pass 1 with equi-width bins does not cut the pass count to 1 plus a finish on at least 90 percent of random and logit-like rows, or the per-item cost exceeds the radix extractor by more than 10 percent, drop N6.
