# R12: N2, level-parallel bitonic top-k (sort all tiles at once, halve per level)
status: rejected (2026-10-25, algo-researcher, on the wave 1 cards of opt-W1b and opt-W1)
scope: warp, subwarp
seed: the N2 idea card (Shanbhag style pruned bitonic top-k on a register-striped warp)
idea: replace W1's sequential tile loop (sort every tile, merge into the retained set) by sorting all N over k tiles at once and merging pairs level by level, so the dependent chain is log2(N over k) levels instead of N over k merges.
reason: with identical network code and policies the restructuring gains nothing. opt-W1b measured it against the eager loop on the same packed words in one session (card W1_level_same_b200_20261025_1): the kill cell N 64 k 32 is 0.96x bf16 and 1.00x fp32, N 128 to 256 at k 32 to 64 is 0.95x to 1.08x, throughput within 3 percent, 2 more registers. At sub-warp scope with 4 to 16 tiles (W1_level_same_sub) 0.91x to 1.17x with 11 to 30 more registers. On pairs (W1_level_pairs) 0.96x at the kill cell and 1.09x to 1.22x at N 128 to 256 with 16 more registers and equal or lower throughput. The shuffle count is identical by construction and ptxas already overlaps the eager loop's independent tile sorts, which the N2 cost model counted as sequential.
evidence: cards W1_level_same_b200_20261025_1, W1_level_same_sub_b200_20261025_1, W1_level_pairs_b200_20261025_1 (B200, nvcc 13.4.92, same lock sections). opt-W1's W1_level network (cards N2_level_gb200_20261025_1 and N2_level_sub) measured 1.5x to 2.5x over CUB's network on the same packed word from four tiles on, but its exchange is two predicated VIMNMX per stage against CUB's ISETP, ISETP, PLOP3, SEL, and it is written with template recursion (T34, T36), so the gain is the network implementation and not the level structure. The two findings do not contradict each other once the exchange is held fixed, the experiment that separates them is in `ideas/PRIORITIES.md`.
what survives: the VIMNMX exchange form and the codegen rules (T28, T34, T36) go to W1's card as its network implementation, independent of the loop order. The level loop itself is not worth a code path.
