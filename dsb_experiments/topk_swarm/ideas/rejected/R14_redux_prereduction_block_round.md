# R14: Warp pre-reduction before the shared atomic of a block round
status: rejected (2026-10-25, algo-researcher, on opt-B2b's card B2_redux8_b200_20261025_1 and catalogue T26, T27, T33)
scope: block
seed: the B2 card's exploration of the round (post one warp maximum per warp instead of 256 atomics), and the July hybrid redux plus atomic variant
idea: reduce each warp's 32 candidates with `__reduce_max_sync` and let one lane post the result, so the shared memory unit sees 8 atomics per round instead of 256.
reason: ptxas already aggregates a warp's same-address fire-and-forget `atomicMax` into one CREDUX.MAX plus one elected ATOMS (T26, T27), so the plain atomic round is the pre-reduced round. The hand-written form adds a second CREDUX (ptxas re-aggregates the predicated single-lane atomic: VOTEU, CREDUX, UFLO), a BSSY and BSYNC region for the lane test and the IMAD move of the uniform result, 55 to 75 cycles per round. Measured against B2_twolevel in one lock section: latency 0.54x to 0.97x (median 0.70x), throughput 0.57x to 0.96x (median 0.82x) over 48 shapes, both requirements alike. The same mechanism explains the July observation that an explicit redux plus elected atomic was slower than the plain burst (T11, 148 against 74), and T33 says the CREDUX throughput per scheduler (about 5.5 cycles each) was never the limit.
evidence: card B2_redux8_b200_20261025_1 (B200 umbriel-b200-091, nvcc 13.4.92), round SASS 20 instructions against 10, CREDUX 64 against 32 kernel-wide. T26, T27, T33 in `TECHNIQUES.md`.
what survives: the floor for posting a warp's candidates to one shared word is the aggregated form, write the plain atomic and let ptxas do it. A warp-level pre-selection pays only when it removes rounds (B5's warp phase), which R13 closed as well.
