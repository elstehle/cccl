## 2. The open contradiction in the W1 family and the one experiment that resolves it

opt-W1 (GB200, cards N2_level_gb200 and N2_level_sub) measured its level network 1.5x to 2.5x faster than CUB's `WarpBitonicTopK` on the same packed bf16 word from four tiles on (N 128 k 16 883 against 1367, N 256 k 32 1115 against 2841) and up to 4.2x at sub-warp scope. opt-W1b (B200, cards W1_level_same and W1_level_same_sub) measured the level order against the eager order with identical network code at 0.95x to 1.08x. Both are right, they held different things fixed. opt-W1's network differs from CUB's in the exchange (two predicated VIMNMX per stage against ISETP, ISETP, PLOP3, SEL) and in its codegen (template recursion, no lambdas, T34 and T36), opt-W1b's comparison changed only the loop order. The lever is therefore in the network implementation, not in the level structure and not in the shuffle policy (opt-W1's split-shuffle variant measured 1.00x).

The experiment: one session on one x86 host (T20 forbids mixing hosts for networks), four kernels on the same packed bf16 u32 word and the same fp32 u64 word, N 128 and 256, k 32, both regimes: (a) CUB exchange in eager order (W1_eager_same), (b) CUB exchange in level order (W1_level_same), (c) opt-W1's VIMNMX exchange in eager tile order, (d) opt-W1's VIMNMX exchange in level order (W1_level). If (c) is within 10 percent of (d) and both are 1.5x or more under (a), the gain is the exchange and W1's card adopts it with the eager loop (one code path, no register growth). If (d) is well above (c), the level structure pays only together with the VIMNMX exchange and R12 is reopened for that combination. Kernel (c) is the one that does not exist yet and costs an hour to write from opt-W1's source.
