## 2. The W1 contradiction, resolved (card W1x_codegen, T42)

Four kernels in one session on one x86 host: the exchange written as min and max (two predicated VIMNMX per stage) is worth 1.15x to 1.59x over CUB's compare and select chain on the same network, the template recursion with compile-time indices 1.03x to 1.41x over the CUB header, and the level tile order 1.15x to 1.54x only with one word per tile (M 1, N at least 4 MaxK) and 0.93x to 1.00x with two words per tile. The factors multiply (1.03 x 1.15 x 1.15 = 1.36 at N 128 k 32, 2.17 at N 256 k 32). opt-W1's 1.5x to 2.55x on GB200 additionally carried a 1.17x to 1.26x penalty of the aarch64 cicc on the CUB header path (a longer ISETP chain, no branches), which the explicitly written networks do not have. opt-W1b changed the order alone inside an implementation that did not expose the overlap and saw none of the three. In throughput only the exchange matters (1.10x to 1.24x). Consequences: R12 stays rejected as a general path (the level order is an M 1 latency option only), W1's bf16 code path is the min max exchange on the recursion in eager order (W1x_vimnmx_eager, 1.18x to 2.24x over CUB's primitive, 1.08x to 1.29x throughput), and cub::detail::WarpBitonicTopK would need a min max customization point next to its comparator to get it. Open for one hour: the same attribution on the fp32 u64 word (no VIMNMX exists for it).
