Every number carries arch, CUDA version, node, date and the microbenchmark file. The knowledge curator folds entries into `TOPK_KNOWLEDGE_BASE.md` at every wave boundary. Entry ids are `T<n>`, assigned in order of appending.

evidence: <SASS lines, file, or report section>
how to use: <one paragraph>
caveats: <where it does not hold>
author: <agent>

### T1: redux.sync.max.u32 costs about 22 cycles and compiles to one CREDUX
applies to: W2, B2 and B5 warp phases, any warp max or sum of 32-bit keys, all key widths once twiddled or packed into 32 bits
measured: redux.sync.max.u32 dependent chain B200 21.9, GB200 21.9 cycles per call. For comparison shfl_xor single B200 30.0, GB200 30.0, 5-shuffle max tree u32 B200 150.0, GB200 150.0, f32 (fmaxf) B200 150.0, GB200 150.0, u64 B200 189.8, GB200 189.8, ballot B200 26.7, GB200 26.7. B200 = NVIDIA B200 sm_100, umbriel-b200-020, nvcc 13.4.92, 2026-10-25. GB200 = NVIDIA GB200 sm_100, gb200-nvl4-ts2-92, nvcc 13.4.92, 2026-10-25. Chain-slope method of BRIEF section 4, min of 64 repetitions, file harness/micro/intrinsics_micro.cu, rows named as in the JSON under state/results/hw-researcher/<node>/.
evidence: `CREDUX.MAX UR5, R9` then `IMAD.U32 R9, RZ, RZ, UR5` (the result lands in a uniform register and is moved back), sass_sm_100.txt kernel `bench<ReduxU32, 4>`. The July 2026 numbers (22.4 redux, 30 shuffle, 150 and 190 trees) re-verified within one cycle on CUDA 13.4.92.
how to use: One redux replaces a 5-step shuffle tree (about 7 times cheaper) for any 32-bit integer reduction. The result is warp-uniform, so a following `lane == winner` test needs the per-lane value compared against it, see the W2 round entry.
caveats: Integer types only on the sm_100 baseline target. `.add` truncates to 32 bits. The uniform-register destination means the value is not in a per-lane register until the IMAD move, which the compiler inserts.
author: hw-researcher

GB200 = NVIDIA GB200 sm_100, gb200-nvl4-ts2-92, nvcc 13.4.92, 2026-10-25. ### T3: a W2 extraction round costs 89 cycles unpacked and 34 cycles with the index packed into the key
applies to: W2 redux based extraction at warp scope, B5 warp phases, keys of 16 bits or less (packed) and 32-bit keys (unpacked)
measured: unpacked round (redux max, ballot of `v == max`, ffs, winner select) B200 88.6, GB200 88.6 cycles. Packed round (redux max of `key << 16 | index`, winner by `v == max`) B200 35.5, GB200 35.5 cycles. Components: ballot + ffs + winner select alone B200 74.5, GB200 74.5, `__ffs` alone B200 40.0, GB200 40.0, redux alone B200 21.9, GB200 21.9. Warp max through 32 fire-and-forget shared atomics + syncwarp + LDS B200 48.6, GB200 48.6. B200 = NVIDIA B200 sm_100, umbriel-b200-020, nvcc 13.4.92, 2026-10-25. GB200 = NVIDIA GB200 sm_100, gb200-nvl4-ts2-92, nvcc 13.4.92, 2026-10-25. Chain-slope method of BRIEF section 4, min of 64 repetitions, file harness/micro/intrinsics_micro.cu, rows named as in the JSON under state/results/hw-researcher/<node>/.
evidence: unpacked kernel `bench<ReduxBallotRound, 4>`: `CREDUX.MAX`, `VOTE.ANY`, `BREV`, `FLO.U32.SH`, `ISETP` per round. Packed kernel `bench<ReduxPackedRound, 4>`: `CREDUX.MAX`, `ISETP`, `LOP3`, `SHF` per round (sass_sm_100.txt).
how to use: For keys of 16 bits or less, pack `(twiddled_key << 16) | (0xffff - index)` and every round is one redux plus a compare, 2.6 times cheaper than the unpacked round, deterministic and prefer-smaller-index for free. For 32-bit keys the ffs is the expensive part (BREV + FLO, about 40 cycles): resolve the winner with `__ballot_sync(v == m)` and `%lanemask_lt` based rank tests or a second redux of the lane id instead of `__ffs` when the critical path matters.
caveats: The packed form caps the index at 65535 per segment. At warp scope a redux round (22) beats the shared atomic round (49), the opposite of block scope where the atomic256 round wins (see the block max entry). The July figure of 82 cycles for the unpacked round is 89 here because this round includes the winner select.
author: hw-researcher

B200 = NVIDIA B200 sm_100, umbriel-b200-020, nvcc 13.4.92, 2026-10-25. GB200 = NVIDIA GB200 sm_100, gb200-nvl4-ts2-92, nvcc 13.4.92, 2026-10-25. Chain-slope method of BRIEF section 4, min of 64 repetitions, file harness/micro/intrinsics_micro.cu, rows named as in the JSON under state/results/hw-researcher/<node>/.

applies to: W3 digit histograms, duplicate detection and tie handling with `__match_any_sync`, warp scope
measured: cycles per call with U distinct values among 32 lanes: U=1 B200 51.4, GB200 51.4, 2 B200 61.9, GB200 61.9, 4 B200 83.9, GB200 83.9, 8 B200 127.9, GB200 127.9, 16 B200 215.9, GB200 215.9, 32 B200 391.9, GB200 391.9. B200 = NVIDIA B200 sm_100, umbriel-b200-020, nvcc 13.4.92, 2026-10-25. GB200 = NVIDIA GB200 sm_100, gb200-nvl4-ts2-92, nvcc 13.4.92, 2026-10-25. Chain-slope method of BRIEF section 4, min of 64 repetitions, file harness/micro/intrinsics_micro.cu, rows named as in the JSON under state/results/hw-researcher/<node>/.
evidence: `MATCH.ANY R6, R9` then `POPC R7, R6` per call, one SASS instruction whose latency grows with the number of distinct values (sass_sm_100.txt, `bench<MatchAnyClasses<32>, 4>`).

### T6: elect.sync is one SASS instruction whose latency hides behind a redux, no cheaper than ffs(activemask) but deterministic
applies to: the one-lane work after any warp reduction (shared memory write, atomic, counter), all scopes
measured: redux chain alone B200 21.9, GB200 21.9 cycles, redux chain with an `elect.sync` per step feeding the next input B200 29.0, GB200 29.0, the same with `__ffs(__activemask()) - 1` B200 29.3, GB200 29.3. The increment of about 6 cycles is the adds that consume the leader id, not the election. B200 = NVIDIA B200 sm_100, umbriel-b200-020, nvcc 13.4.92, 2026-10-25. GB200 = NVIDIA GB200 sm_100, gb200-nvl4-ts2-92, nvcc 13.4.92, 2026-10-25. Chain-slope method of BRIEF section 4, min of 64 repetitions, file harness/micro/intrinsics_micro.cu, rows named as in the JSON under state/results/hw-researcher/<node>/.
evidence: `ELECT P0, UR8, PT` (sass_sm_100.txt, `bench<ReduxElect, 4>`), the ffs variant is `VOTEU.ANY`, `UBREV`, `UFLO.U32.SH` on the uniform datapath (`bench<ReduxFfsLeader, 4>`).
how to use: `elect.sync` (inline PTX or `cuda::ptx::elect_sync`) is free when issued next to a reduction because it does not depend on the data, and it is deterministic (the same lane every time for the same mask), which `__activemask()` after divergence is not. B200 = NVIDIA B200 sm_100, umbriel-b200-020, nvcc 13.4.92, 2026-10-25. GB200 = NVIDIA GB200 sm_100, gb200-nvl4-ts2-92, nvcc 13.4.92, 2026-10-25. caveats: Contention numbers are self-dependent chains per thread (every thread waits for its own return), the realistic round pattern is in the block max entry.
author: hw-researcher

### T10: fire-and-forget same-address shared atomics issue for free once per warp per round but serialize at 32 to 59 cycles when a warp repeats them back to back
applies to: B2 rounds (one atomic per thread per round), shared memory histograms (many atomics per thread), block scope
measured: pair chains with 8 fire-and-forget `atomicMax` per step interleaved with 8 dependent IMADs, against the IMAD base (B200 31.8, GB200 31.8 at 32 threads, B200 31.5, GB200 31.3 at 256): 1 lane on the slot and 31 on private words B200 31.5, GB200 31.5 (the atomics are hidden entirely), 32 lanes on one slot B200 446.1, GB200 446.1, 256 threads on one slot B200 2036.3, GB200 2028.1. Bursts of 8 independent atomics per step: 32 on one slot B200 475.6, GB200 475.6, 256 on one slot B200 2034.5, GB200 2037.0, 256 threads on 256 private words B200 71.9, GB200 71.5. One same-slot atomic per thread per round inside a block round: see the block max entry (74.5 cycles for the whole round including barrier and read back, 0 mismatches in the completion check). B200 = NVIDIA B200 sm_100, umbriel-b200-020, nvcc 13.4.92, 2026-10-25. GB200 = NVIDIA GB200 sm_100, gb200-nvl4-ts2-92, nvcc 13.4.92, 2026-10-25. Chain-slope method of BRIEF section 4, min of 64 repetitions, file harness/micro/intrinsics_micro.cu, rows named as in the JSON under state/results/hw-researcher/<node>/.
evidence: `ATOMS.MAX RZ, [R6], R7` (destination RZ, no return) with the address selected by `SEL`, no branch (`bench<AtomNoRet<unsigned, 256, 256>, 2>`, sass_sm_100.txt). Completion: `bench<BlockMaxAtomic256Check<unsigned>, N>` compares the slot read after `BAR.SYNC` with a shuffle tree max and counted 0 mismatches in 64 repetitions at every chain length on every node measured.
how to use: The B2 pattern (every thread one `atomicMax` into `slot[round]`, barrier, read) is cheap because the slot address is warp-uniform and ptxas aggregates the warp's 32 same-address fire-and-forget atomics into one `CREDUX.MAX` plus one atomic by an elected lane (T26 and T27 by opt-B2b, visible in `bench<BlockMaxAtomic256<unsigned>, 4>` as `CREDUX.MAX`, `VOTEU.ANY`, `UFLO`, `@P0 ATOMS.MAX RZ`), so eight atomics reach the shared memory unit per round and the read after the barrier is correct. Keep that address provably uniform (indexed by a round counter, never by per-thread data): the burst rows above select the address per thread, ptxas cannot aggregate them, and the hardware then serializes same-address lanes at about one per cycle (32 to 59 cycles per warp instruction). A shared memory histogram with data-dependent bins is in that regime, so pre-combine equal keys in registers or spread hits over banked copies, 256 threads over 256 private words issue at about 9 cycles per warp instruction.
caveats: The first version of this entry attributed the cheap round to merging inside the shared memory atomic unit, the SASS shows it is ptxas aggregation at compile time, which only happens for a provably uniform address without a returned value. The u64 fire-and-forget form is the CAS loop of the previous entry and skips the atomic when the value is not larger, so its burst number (B200 716.3) is not comparable.
author: hw-researcher

how to use: In lockstep logical warps never pass a per-group mask to redux.sync. Issue the collective for every group over the full warp with the identity element (0 for max and add, all ones for min) in the lanes of the other groups, and pick the own group's result with a select chain. The G reductions are independent and pipeline, so the cost is one redux latency plus about 6 cycles per further group. The same holds for `__reduce_add_sync` and `__reduce_min_sync` in the tie pass. Shuffle trees (log2 T steps of 30 cycles) cost about the same as the pipelined redux only at T 4 and more at T 8 and 16.
caveats: One toolkit (nvcc 13.4.92). At T 4 the eight full-warp reductions cost 88 cycles per round, so a shuffle-xor tree of two steps (about 72) may still be preferable there, not measured. The trick assumes all groups of the hardware warp run the same round count in lockstep (true for a fixed k). Block-wide the per-scheduler CREDUX budget of T33 applies (G redux per round per warp).
